# XOT / OpenRouter Incident Post-Mortem (2026-09-13)

**Status:** Resolved (mitigations deployed; OMP restart required for full effect)  
**Severity:** High — all OMP sessions blocked on `:free` models  
**Reset:** 2026-09-14 00:00 UTC (daily counter)

---

## Executive summary

Users saw `429 Rate limit exceeded` loops, `Add 10 credits to unlock 1000 free model requests`, and advisor `quota exhausted` — while believing KEY_01 ($11 paid credits) should still work.

**Root cause was NOT one bug.** It was a stack of interacting failures:

1. **KEY_01 actually exhausted** its separate `:free` daily counter (0/1000), independent of USD balance.
2. **Backup keys** (KEY_02–05) also hit their 50/day caps → `Add 10 credits` message (wrong key tier).
3. **`/uncool` only cleared local COOL** and re-selected KEY_01 — it did **not** restore OpenRouter quota.
4. **3+ simultaneous OMP sessions** all consumed KEY_01 quota (main + advisor + retries per session).
5. **No session locks** → sessions fought over the same key; rotation state was racy.
6. **Legacy `xot.ts` still loaded** in running sessions → spam + broken rotation (same `...9f89` × 15 retries).
7. **`high-balance` 429 mis-handling** → KEY_01 not cooled/rotated when it should have been.

## What the errors actually meant

| Error string | Which key | Meaning |
|--------------|-----------|---------|
| `free-models-per-day-high-balance` | **KEY_01** (`...9f89`) | $10+ account tier, **1000 :free/day exhausted** (0/1000) |
| `free-models-per-day. Add 10 credits...` | **Backup keys** (KEY_02–05) | **<$10 tier**, **50 :free/day exhausted** (0/50) |
| `Provider returned error` | Often KEY_06–15 during heavy probe | Upstream/shared pool or transient — **not** "buy credits" |
| `retry.maxDelayMs exceeded` | Any | Daily cap retry-after ~6–24h; OMP won't wait that long |

**Critical misconception:** `$11 purchased credits` enables the **1000/day tier** but does **not** bypass the daily free-request counter. Dashboard USD usage ($0.038/day) is unrelated to `:free` request count.

- 15 keys = **15 independent `creator_user_id`** (not shared account balance).

## Timeline of confusion — why we kept missing it

### 1. Wrong key blamed for `Add 10 credits`

User ran `/uncool` → UI said `Active: sk-or-…9f89 (KEY_01)`.

Then error showed `Add 10 credits` → user thought KEY_01 needed more payment.

**Reality:** Flow was KEY_01 → 429 (`high-balance`) → auto-fallback to backup → backup 429 (`Add 10 credits`). The visible message was from the **backup**, not KEY_01.

### 2. Dashboard vs free counter

OpenRouter dashboard: `$0.038/day` USD. User: "I didn't use 1000 requests."

**Reality:** Free `:free` requests are a **separate counter**. Consumed by:
- Main agent requests
- Advisor (separate API calls, same key)
- Free-swarm / jury workers
- Failed retries (may still count)
- **Multiple OMP sessions** sharing KEY_01

### 3. Same suffix `...9f89` on every retry

Logs: `Warning: xot: daily cap on sk-or-...9f89 -> trying sk-or-...9f89 (12/15)`

**Reality:** Rotation was **broken** — not 15 independent accounts sharing one balance. `key-rotate-lite` wasn't loaded; legacy `xot.ts` was still active in old sessions.

### 4. `high-balance` regex bug (fixed mid-incident)

`isDailyCap429()` initially **excluded** `high-balance` from daily-cap detection.

Effect: KEY_01 at 0/1000 did **not** enter COOL → kept retrying same key.

### 5. Extension changes not active until restart

5 `omp --resume` processes loaded extensions at startup. Config disabled `xot.ts` but **running sessions kept old code**.

Symptoms persisted after file edits until restart.

### 6. Multi-session = silent quota multiplier

```
Session A → pick → KEY_01
Session B → pick → KEY_01
Session C → pick → KEY_01
```

Each: main + advisor + retries. **~3× burn rate** on KEY_01's 1000/day with no coordination.

### 7. `/uncool` semantics misunderstood

| What user thought | What it actually did |
|-------------------|----------------------|
| Refill OpenRouter quota | Clear local `COOL_*` entries in `~/.local/daemon/xot/state` |
| Force working key | Re-select KEY_01 (primary-first policy) |
| Fix advisor | Reset advisor pause flag only |

### 8. File corruption during rapid edits

`key-rotate-lite.ts` was truncated mid-edit → OMP `Failed to parse extension` → fixes didn't load → appeared "still broken."

### 9. Initial hypothesis: shared balance across 15 keys

Early theory: all keys share one OpenRouter balance.

**Disproved:** Each key has distinct `creator_user_id`. Caps are per-account, but **usage pattern** made it look shared because all sessions picked KEY_01.

## How it was fixed

### Phase 1 — Stop the bleeding

| Change | File |
|--------|------|
| Disable legacy XOT stack (`xot.ts`, `auto-rotate`, etc.) | `~/.omp/agent/config.yml` |
| Add `key-rotate-lite.ts` | Thin wrapper around `xot-rotate` |
| Remove `openrouter-paid-auto` | `openrouter-free-swarm.ts`, config |
| Fix `high-balance` daily-cap classification | `key-rotate-lite.ts` |
| Advisor → `openrouter-free-auto/best-reason` only | `advisor-manager.ts` |

### Phase 2 — Correct operations

| Feature | Behavior |
|---------|----------|
| `sync_quota` / improved `/uncool` | Probe OpenRouter; cool exhausted keys; pick first **working** key |
| `/key N` | Manual KEY_N override |
| `xot-rotate probe` | Live quota check per key |
| Docs + Notion | `xot-rotation.md` |

### Phase 3 — Multi-session locks (2026-09-13 final)

| Component | Path | Role |
|-----------|------|------|
| `xot-lock.py` | `~/.local/daemon/xot/xot-lock.py` | Session → key registry |
| `flock` | `~/.local/daemon/xot/locks/.flock` | Serialize state mutations |
| `acquire <sid>` | `xot-rotate` | Auto-assign exclusive key per OMP session |
| `release <sid>` | On `session_shutdown` | Free key for other sessions |
| `locks` | Status command | Show who holds which key |

**Policy:** Session start → auto-acquire first free key. `/key N` is this-session-only and **refuses** if another live session holds that key.

**Verified:** 3 test sessions → KEY_06, KEY_07, KEY_08 (distinct keys).

### Phase 4 — Isolation hardening (2026-09-14)

Audit of live lock behavior found three remaining isolation bugs:

1. **`/key N` stole other sessions' locks** (`force()` deleted the owner). Both processes then used the same key (victim kept it in memory).
2. **Idle 5-minute heartbeat prune** dropped locks of live but quiet OMP sessions → another session could take the key while the first still used it.
3. **`/uncool` / `sync_quota` probed every key**, including ones locked by other sessions, burning their `:free` quota.

Fixes (xot-lite **1.0.1-20260914**):

| Change | Behavior now |
|--------|----------------|
| `/key N` | Refuses if locked (`KEY_N is locked by session …`). `/key N steal` is explicit. |
| `/key-rotate` | Bumps **this** session only. Other registry entries unchanged. |
| Per-request `acquire` | Sticky re-confirm so a process cannot keep a stolen/pruned key. |
| Lock lifetime | Live PID keeps the key (no 5-min expiry). Dead PID pruned immediately. |
| `sync_quota` | Skips keys locked by other sessions. |
| Session acquire/bump | Does **not** rewrite global `ACTIVE_IDX`. |
| `pick` | Fails rather than returning a locked key. |

**Verified (isolated, no live API):** bump leaves other session; `/key` on a free key leaves other session; `/key` on a locked key refuses and owner keeps it; `--steal` evicts only when asked; idle live PID is not pruned.

## Lessons learned

1. **Never trust dashboard USD for `:free` quota** — probe or read 429 headers.
2. **Error message identifies the key tier** — `high-balance` ≠ `Add 10 credits`.
3. **`/uncool` ≠ quota refill** — now syncs with OpenRouter.
4. **Multi-session requires locks** — primary-first without locks = quota multiplier.
5. **Restart OMP after extension edits** — file changes don't hot-reload in resume sessions.
6. **One symptom, many bugs** — fix stack holistically, not one regex at a time.
